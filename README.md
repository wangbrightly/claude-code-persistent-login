# Claude Code CLI 免每日重新登录指南

**读者对象**：会照着终端敲命令，但不熟悉 OAuth、令牌（token）、环境变量、钥匙串这些概念的普通用户。文中第一次出现这类词，会先用一句大白话解释，再继续往下讲。

**关于凭据**：本文所有令牌、密钥都写成 `[YOUR_TOKEN]` 这样的占位符。**不要**把你自己的真实令牌粘贴到任何公开仓库、聊天记录或截图里——它等同于你账号的密码，泄露后任何人都能拿它冒充你调用你的 Claude 订阅额度。

---

## 1. 现象

如果你每天（或每隔约 24 小时）第一次打开终端运行 `claude` 时，都会被要求重新走一遍网页登录流程（`/login`），哪怕你前一天明明已经登录成功、也没有主动退出过——你遇到的很可能就是本文要解决的问题。

> **[待补充]**：本机报错的逐字原文和截图，因为撰写本文时问题当下没有复现在眼前，没有现场抓取。如果你在自己机器上遇到，可以把 `claude --debug` 的输出保存下来，那是最直接的证据。

## 2. 成因

**已核实（截至 2026-09-15）**：这是 Claude Code 的一个**尚未修复的已知 bug**，社区已经有人提交了报告：

- [anthropics/claude-code#78037](https://github.com/anthropics/claude-code/issues/78037)（状态：open）——报告者用 Windows 单机，描述"约 24 小时后 refresh token 被服务器拒绝，被迫每天 `/login`"，症状与本文描述的现象一致。评论区里还有其他人反映过同样的失败特征。
- 该 issue 下**没有**任何官方回复认领这是已修复或即将修复的问题，也没有官方推荐的绕过方法——下面第 3 节的解决办法是社区/自行摸索出来的**规避手段**，不是官方补丁。

**一句话说清成因**：Claude Code 正常登录后，本机会保存两样东西——一个短期"通行证"（access token，几小时后失效）和一个用来换新通行证的"长期凭证"（refresh token，正常应该能用很久）。这个 bug 的表现是：refresh token 明明还在本机、也没被改动过，但服务器那一端却提前把它拒收了，导致 CLI 只能强制你重新走网页登录。

**推测、未完全证实的部分**：具体是服务器端的哪个环节提前让 refresh token 失效（会话数量限制？多进程冲突？纯粹的服务端 bug？），目前没有定论，issue 里也众说纷纭。**注意**：早期有一种"多个并发会话互相抢占导致 token 轮换竞态"的猜测（对应另一个已经在 2026-05-07 被官方标记为"已完成修复"的旧 issue #24317），但那是另一个更早的、已关闭的问题，跟本文描述的现象不是同一件事，不要把两者混为一谈。

## 3. 解决步骤：用长期令牌绕开每日登录

**思路**：Claude Code CLI 自带一个 `setup-token` 命令，可以生成一个**长期有效的静态令牌**，把它设置成环境变量后，CLI 会优先用这个令牌，不再走会被服务器提前拒绝的那套自动续期流程，从而绕开这个 bug。

> "环境变量"是什么：一种在你打开终端时就自动生效的、系统级的"设置项"，程序启动时会去读它。设置一次，以后每次开终端都自动生效，不用每次手动输入。

### 3.1 生成长期令牌

```bash
claude setup-token
```

运行后会提示你完成一次性的网页授权（和平时 `/login` 类似）。**成功时你应该看到**：终端打印出一长串字符——这就是你的长期令牌。把它复制下来（先别关终端窗口）。

> 前提：这个命令需要你有 Claude 订阅账号，命令本身的帮助文字写明了"requires Claude subscription"。

### 3.2 把令牌写进 shell 配置文件

先备份，再改——这是修改配置文件前的标准动作，出问题随时能恢复：

```bash
cp ~/.zshrc ~/.zshrc.bak.$(date +%Y%m%d)
```

> 如果你用的是 bash 而不是 zsh，把上面和下面的 `~/.zshrc` 换成 `~/.bash_profile`（Mac 常见）或 `~/.bashrc`（Linux 常见）。不确定自己用哪个 shell，运行 `echo $SHELL` 看一眼。

用文本编辑器打开 `~/.zshrc`，在文件末尾加一行（把 `[YOUR_TOKEN]` 换成你上一步拿到的那一长串字符）：

```bash
export CLAUDE_CODE_OAUTH_TOKEN=[YOUR_TOKEN]
```

保存文件。

### 3.3 让配置生效

```bash
source ~/.zshrc
```

**成功时你应该看到**：命令执行后没有任何报错，光标正常回到提示符。

## 4. 验证

**第一步，确认变量已经设置好**（只检查长度，不把真实令牌打印到屏幕或截图里）：

```bash
echo ${#CLAUDE_CODE_OAUTH_TOKEN}
```

**成功时你应该看到**：一个大于 0 的数字（令牌的字符长度）。如果输出是 `0`，说明上一步没生效，回去检查 `~/.zshrc` 里那行有没有写对、有没有 `source` 过。

**第二步，实际验证是否真的免登录**：新开一个终端窗口（或者电脑重启后），直接运行：

```bash
claude
```

**成功时你应该看到**：直接进入正常的对话界面，不再弹出要求你 `/login` 的提示。真正的验证要**过 24 小时以上再看一次**，因为这个 bug 本来就是隔一段时间才发作。

## 5. 失效与回滚

**这个方法在什么情况下可能会失效**：

- `[待补充]`：`setup-token` 生成的长期令牌本身是否也有过期时间（比如几个月），目前没有查到官方文档明确说明，需要长期观察。
- 如果 Anthropic 官方后续修复了 #78037 描述的服务端 bug，或者调整了长期令牌机制，这个规避方法可能需要跟着调整——写这篇文档时问题仍是开放状态。
- 如果你同时又手动运行了 `/login`，两套登录方式可能互相覆盖，行为不确定。

**如何回滚到原来的样子**：

删掉（或注释掉）你在 `~/.zshrc` 里加的那一行，然后：

```bash
source ~/.zshrc
```

或者直接用备份文件覆盖回去：

```bash
cp ~/.zshrc.bak.日期 ~/.zshrc
source ~/.zshrc
```

回滚后，Claude Code 会恢复成正常的网页登录流程（也就是会重新遇到本文开头描述的那个每日登录问题）。

## 6. 适用前提

- 操作系统：macOS 或 Linux，使用 zsh 或 bash 作为默认 shell。Windows 用户设置环境变量的方式不同，`[待补充]`，本文未覆盖。
- 已经安装好 Claude Code CLI，且能正常运行 `claude` 命令。
- 拥有有效的 Claude 订阅（`setup-token` 命令的前提条件）。
- CLI 版本：本文验证环境为 `2.1.272`。更早或更晚的版本是否有差异，`[待补充]`。
